Meridian prototype · reconciliation report ·

An actuarial projection engine that reconciles to the cent

Meridian is a prototype alternative to Prophet-style modelling: actuaries write variables as formulas in Python, and a Rust engine projects them across policies, scenarios and months. To test it against something independent, two published open-source models from lifelib were rebuilt in Meridian and checked policy by policy against lifelib's own results.

Designed and written by an AI assistant (Claude), directed by one actuary. Every number on this page comes from a run of the code.

Meridian lifelib (reference)

Model 1 · lifelib BasicTerm

Term assurance, 10,000 policies

Monthly projection over 20 years with select-and-ultimate mortality (attained age × duration, five-year select period), duration-based lapses, inflating expenses and first-year commission. The premium is 150% of the net premium, so the model runs twice: once to price, once to project.

Portfolio cash flows by month

Model 2 · lifelib CashValue_ME

Stochastic savings, 10 scenarios at once

A universal-life style product with an account value: single and level premiums, premium loadings, a monthly fee, cost of insurance on the net amount at risk, death benefit of the greater of sum assured and account value, surrender charges by product and duration, whole life to age 115, and lognormal fund returns. lifelib runs one scenario per call; Meridian runs all ten in one pass. A second set turns 1,000 policies into in-force business, with durations and account values, to test the existing-business logic as well.

Portfolio PV of net cash flow, by scenario

Each lifelib dot sits inside its Meridian ring. The values agree to four decimal places on numbers of about 50 billion.

For Prophet users

Familiar concepts, different machinery

Meridian keeps the way a Prophet modeller thinks, with variables defined by formulas over time, products, tables, runs and accumulations, and changes what sits underneath.

Scope

What this shows, and what it does not

It shows that a Python modelling language over a compiled engine can reproduce independent published models exactly. That covers stochastic, in-force and account-value mechanics as well as simple term assurance, and it does so fast. The engine's results are bit-for-bit identical whatever the thread count or batch size, and each lifelib comparison is repeatable from the repository.

It does not show a comparison with Prophet itself. No Prophet software, code or documentation was used. The models are lifelib's illustrative ones, not certified regulatory libraries. Nested stochastic runs, goal-seek, arrays and the governance features in the product spec are still to build.

Reproduce

cd meridian
python -m maturin develop --release     # build the Rust engine into a virtual env
python -m pytest -q                     # reconciliation tests (lifelib, NumPy reference)
python examples/run_lifelib_basicterm.py
python examples/run_lifelib_cashvalue.py --extra-scenarios 100
